# AniWatch Media

A small static editorial dashboard for the public Telegram channel `@aniwatch_1`.

## Current v1 scope

- Drafts stored in the current browser's localStorage.
- Plain-text post editor and preview.
- Optional public HTTPS image URL.
- Manual publish to Telegram after a browser confirmation.
- Publish history counter stored locally in the current browser.
- Cloudflare Worker acts as a private bridge to Telegram Bot API.

**Not implemented yet:** server-side draft sync, automatic scheduled publishing, Telegram analytics, comments inbox, AI generation, and multi-user accounts. A browser-local draft is not backed up or shared between devices.

## Architecture

- GitHub Pages hosts `index.html`.
- Cloudflare Worker in `worker/worker.js` holds Telegram credentials and sends posts.
- Telegram Bot API publishes to `@aniwatch_1`.

No OpenAI API key is required.

## 1. Configure the Telegram bot

1. Create a bot using Telegram's official `@BotFather` and copy its token.
2. Add the bot as an administrator of `@aniwatch_1`.
3. Grant only the permission required to post messages.
4. Keep the bot token private. Never place it in this repository or in the browser.

The channel target can be the public username `@aniwatch_1`.

## 2. Deploy the Cloudflare Worker

1. Create a free Cloudflare account and open Workers & Pages.
2. Create a Worker named, for example, `aniwatch-media-bridge`.
3. Paste the contents of `worker/worker.js` into the Worker editor and deploy.
4. In Worker Settings → Variables and Secrets, add these values:

| Name | Type | Value |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Secret | Token from BotFather |
| `ADMIN_KEY` | Secret | A long, random password generated by you |
| `TELEGRAM_CHANNEL_ID` | Variable | `@aniwatch_1` |
| `ALLOWED_ORIGIN` | Variable | Exact GitHub Pages origin, e.g. `https://quvok.github.io` |

For `ADMIN_KEY`, use a unique random value of at least 32 characters. Do not reuse your GitHub password or Telegram bot token.

If you use a custom domain for Pages, set `ALLOWED_ORIGIN` to that exact origin instead. Do not include a path or trailing slash.

5. Open `https://YOUR-WORKER.workers.dev/health`. It should return `{"ok":true,...}`.

## 3. Enable GitHub Pages

1. Open repository Settings → Pages.
2. Under Build and deployment, choose **GitHub Actions**.
3. The workflow in `.github/workflows/pages.yml` will deploy the static dashboard after a push to `main`.
4. Wait for the Pages workflow to complete, then open the published URL.

## 4. Use the dashboard

1. Enter the Worker URL in **Адрес Worker API**.
2. Enter the `ADMIN_KEY` in **Ключ доступа панели**.
3. Write a post and optionally add a direct public HTTPS image URL.
4. Click **Опубликовать в Telegram** and confirm the browser prompt.

The access key is kept in the current tab's session memory only. The Worker checks it before contacting Telegram. Drafts are stored locally in the browser.

## Security notes

- Never commit `TELEGRAM_BOT_TOKEN` or `ADMIN_KEY`.
- The bot must be an administrator of the target channel.
- Restrict Worker CORS with the exact Pages origin.
- Anyone who obtains the admin key can publish to the channel. Rotate it immediately if exposed.
- This first version does not implement server-side rate limiting or audit logs. Keep the Worker URL and admin key private.
- Telegram Bot API supports plain text and photo captions here; rich formatting, albums, video, and scheduling are not implemented yet.

## Local development

Open `index.html` through a local static web server. The dashboard can be previewed without configuring the Worker; publishing requires the Worker secrets and bot permissions.
